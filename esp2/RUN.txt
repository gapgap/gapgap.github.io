Three explicitly separate controls in each debug app:
1. Direct OneLink: SDK receives the original OneLink.
2. Hosted ESP: SDK receives the HTTPS tracking URL entered in the app.
3. Local 302: SDK receives localhost/127.0.0.1, and an in-app HTTP server returns
   a real 302 with that platform's exact OneLink in Location.

GitHub Pages limitation:
GitHub Pages can publish the HTML launch page and association JSON files.
It cannot run Python or return these custom HTTP 302 responses.
The defaults https://gapgap.github.io/esp2/redirect (iOS) and
https://gapgap.github.io/esp2/android/redirect (Android) are not working hosted
ESP endpoints on GitHub Pages. Expect INCONCLUSIVE until a real HTTPS ESP
tracking URL is entered. There is no automatic fallback to localhost.

In-app testing:
- iOS: open basic_app.xcworkspace, build Debug, tap ESP.
- Android: open kotlin/basic_app in Android Studio, build Debug, tap ESP redirect test.
- Run Direct OneLink first. Then choose Hosted ESP with a real tracking URL,
  or explicitly choose Local 302 for SDK isolation.
- SDK callbacks are captured before the fruit router, with no extra app decoding.
- Reports show SDK version, source URL, raw deep-link value, link, original_link,
  isDeferred, and local redirect count.
- Both apps retain the SDK version currently selected in their project.
  Android was tested with 6.18.0; the SDK version is included in every report.
- Test UI, HTTP listeners, and loopback cleartext allowances are Debug only.

Standalone server:
  cd /Users/gab.t/Documents/github/gapgap.github.io/esp2
  python3 server.py
  curl -I http://127.0.0.1:8787/esp2/redirect
  curl -I http://127.0.0.1:8787/esp2/android/redirect
The first route returns the iOS OneLink; the second returns the Android OneLink.
No browser JavaScript/meta refresh is used to pretend an HTTP redirect ran.
For public hosted ESP testing, the server needs HTTPS hosting outside GitHub Pages.
